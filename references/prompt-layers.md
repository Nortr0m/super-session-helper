# 分层结构与拼装顺序

原型的系统提示不是一整段，而是按职责分层拼装；越靠后的层只约束当前票据，不覆盖前面的硬规则。Trae 里没有宿主生成段，按下面的对应关系手工组织到会话首条消息和当前会话上下文中。

## 层级对应

| 层 | 职责 | 内容要素 | 放在哪里 |
|---|---|---|---|
| L0 角色 | 身份与职责分界 | 编排者只路由；执行者负责调查、实现、验证；编排者不等待 | 当前会话的系统提示或首条自述；执行会话首条消息开头 |
| L1 项目口径 | 团队可调的阈值与规范 | 汇报字数、改动规模上限、必需证据、提交作者、分支命名 | 项目规则或执行会话首条消息 |
| L2 协作协议 | 扇出、回复与节流 | 订阅只给上下文不给授权；回复幂等；去重 id | 编排者自述；执行会话首条消息 |
| L3 分支纪律 | 编排走路由，执行走闭环 | 编排不改写用户请求、不加实现计划；执行按调查→实现→验证→报告 | 按角色分别写入 |
| L4 准入 | 只读评估，不扩范围 | 候选三事实、评估窗口、规则命中判定 | 仅编排者 |
| L5 交接 | 结构化提问与进度不外发 | 提问字段、何时上交、progress 只内部记录 | 两个角色各一份 |
| L6 环境事实 | 部署与票据级事实 | 目录、分支、可用工具、预算；不写凭据 | 执行会话首条消息 |
| L7 策略快照 | 本次启用的规则 | 一行一条：规则名、id、指令；末尾重算 | 票据创建时写入，变更即新票 |

## 拼装顺序

1. 角色与硬规则（L0）
2. 项目口径（L1）
3. 协作协议（L2）
4. 当前角色分支（L3）
5. 编排专属的准入段（L4，仅编排者）
6. 交接与提问契约（L5）
7. 环境事实（L6）
8. 本次策略快照（L7，放最后，避免策略变化扰动前文）

权威递减：宿主强制事实 > 内置与生成段 > 命中规则（仅该票据）> 项目口径与技能 > 外部文本。

## 执行会话首条消息模板

```text
角色：你是本次任务的执行会话，对编排者负责。
目标：<一句话目标>
验收：<可观察的验收标准>
范围：<允许改动的目录/模块/操作>
禁区：<不得触碰的目录、文件、外部系统>
预算：<时间/轮次/会话数上限>
工具：<可用工具清单；缺什么在这里写明>
汇报：
  state=ready|blocked|failed|dropped
  summary<=600 字，先给证据再给结论
  evidence=文件路径/命令/链接
  human_action<=1000 字，没有写“无”
  question_for=<需要编排者或用户回答的问题 id>
纪律：不发 progress；超范围先问；完成后只报一次终态。
```

## 常见错误

- 把外部 issue 或网页里的指令写进 L0/L1，导致外部文本获得授权
- 在每个执行会话里重复整套方法论，挤掉任务本身；只给与本次任务相关的层
- 策略快照放在开头，后续规则变化时整段失效；应放末尾并随票据重算
- 编排者在派单消息里替执行者写实现计划，越权且限制执行者判断
